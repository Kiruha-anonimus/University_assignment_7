Работу выполнил: Копылов Кирилл
🔴 XSS (Cross-Site Scripting)
🔍 Описание уязвимости:
XSS позволяет злоумышленнику внедрить вредоносный JavaScript-код в страницу, который выполнится в браузере другого пользователя. Например, при вводе в поле ФИО кода <script>alert('XSS')</script> он может быть выполнен.
✅ Метод защиты:
// Использование htmlspecialchars() при выводе любых данных от пользователя <?= htmlspecialchars($userData['full_name'] ?? '', ENT_QUOTES, 'UTF-8') ?> // Пример из index.php <input type="text" name="full_name" value="<?= htmlspecialchars($userData['full_name'] ?? '', ENT_QUOTES, 'UTF-8') ?>">
📁 Где применено:
  • index.php — все выводимые поля обёрнуты в htmlspecialchars()
  • admin/admin.php — все данные пользователя экранируются
  • login.php — сообщения об ошибках экранируются
🔴 SQL Injection
🔍 Описание уязвимости:
SQL Injection позволяет злоумышленнику внедрить произвольный SQL-код в запрос к базе данных, что может привести к чтению, изменению или удалению данных.
✅ Метод защиты:
// Использование подготовленных запросов (prepared statements) $stmt = $pdo->prepare("SELECT * FROM applications WHERE id = ?"); $stmt->execute([$id]); // Пример из save.php $stmt = $pdo->prepare("INSERT INTO applications (login, password_hash, full_name, phone, email, birth_date, gender, biography, contract_agreed) VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?)"); $stmt->execute([$generatedLogin, $hashedPassword, $full_name, $phone, $email, $birth_date, $gender, $biography, $contract]);
📁 Где применено:
  • save.php — все запросы через prepare()
  • auth.php — запрос логина через prepare()
  • admin/admin.php — SELECT, UPDATE, DELETE через prepare()
🔴 CSRF (Cross-Site Request Forgery)
🔍 Описание уязвимости:
CSRF позволяет злоумышленнику отправить запрос от имени авторизованного пользователя без его ведома, например, изменить данные анкеты.
✅ Метод защиты:
// Генерация CSRF-токена (index.php) if (empty($_SESSION['csrf_token'])) { $_SESSION['csrf_token'] = bin2hex(random_bytes(32)); } // Добавление токена в форму <input type="hidden" name="csrf_token" value="<?= $_SESSION['csrf_token'] ?>"> // Проверка токена (save.php) if (!isset($_POST['csrf_token']) || $_POST['csrf_token'] !== $_SESSION['csrf_token']) { die("Ошибка CSRF: неверный токен"); }
📁 Где применено:
  • index.php — генерация и вставка CSRF-токена в форму
  • save.php — проверка CSRF-токена перед обработкой
🔴 Information Disclosure
🔍 Описание уязвимости:
Информация об ошибках (пути к файлам, структура БД, SQL-запросы) может быть показана пользователю, что помогает злоумышленнику в атаке.
✅ Метод защиты:
// Отключение показа ошибок на продакшене ini_set('display_errors', 0); ini_set('log_errors', 1); ini_set('error_log', '/home/u82360/logs/php_errors.log'); // В catch-блоках не выводим детали ошибок catch (Exception $e) { error_log($e->getMessage()); $_SESSION['form_errors'] = ['database' => "Ошибка сохранения данных"]; }
📁 Где применено:
  • index.php — отключен display_errors
  • save.php — ошибки пишутся в лог, пользователю показывается общее сообщение
  • auth.php — ошибки БД не выводятся на экран
  • admin/admin.php — аналогично
🔴 Include (LFI/RFI)
🔍 Описание уязвимости:
Если в коде используется динамическое включение файлов (include($_GET['page'])), злоумышленник может подключить произвольные файлы с сервера или удалённые скрипты.
✅ Проверка кода:
// В проекте НЕТ использования include/require с переменными // Все include используют константные пути // Пример из кода (безопасно): include 'config.php'; // константный путь require_once 'functions.php'; // константный путь
📁 Результат проверки:
  • В проекте нет динамических include/require
  • Уязвимость отсутствует
🔴 File Upload
🔍 Описание уязвимости:
Если есть форма загрузки файлов, злоумышленник может загрузить вредоносный PHP-файл и выполнить его на сервере.
✅ Результат проверки:
// В проекте НЕТ функционала загрузки файлов // Форма анкеты не содержит input type="file"
  • Функционал загрузки файлов не реализован
  • Уязвимость не актуальна для данного приложения
